# ROS2 Gateway Protocol v1

This document defines the WebSocket JSON protocol consumed by the Car UI frontend.

The frontend is a debug and visualization client for an Autoware test sightseeing vehicle. It does not run real planning or vehicle control. In `autoware` planning mode, the frontend sends a goal request through HTTP and waits for `route` / `trajectory` messages pushed by the ROS2 Gateway.

## Transport

- WebSocket endpoint: configured by `window.APP_CONFIG.wsEndpoint`
- Encoding: UTF-8 JSON text frames
- Direction: Gateway to frontend, except HTTP goal submission
- Time unit: Unix epoch milliseconds
- Position unit: meters
- Angle unit: radians
- Velocity unit: meters per second
- Required planning frame for map rendering: `map`

The frontend marks localization as warning when a vehicle pose uses a `frame_id` other than `map`.

## Envelope

Every WebSocket message should include a `type`.

```json
{
  "type": "vehicle_pose",
  "timestamp": 1710000000000,
  "frame_id": "map"
}
```

The frontend accepts both flat messages and messages wrapped in `data`.

Preferred flat form:

```json
{
  "type": "vehicle_pose",
  "timestamp": 1710000000000,
  "frame_id": "map",
  "x": 23.5,
  "y": 14.9,
  "yaw": 1.57,
  "speed": 1.2
}
```

Compatible wrapped form:

```json
{
  "type": "vehicle_pose",
  "data": {
    "timestamp": 1710000000000,
    "frame_id": "map",
    "x": 23.5,
    "y": 14.9,
    "yaw": 1.57,
    "speed": 1.2
  }
}
```

## Message Types

### `snapshot`

Initial state sent when a WebSocket client connects.

```json
{
  "type": "snapshot",
  "protocol": "ros2_gateway.v1",
  "timestamp": 1710000000000,
  "pose": {},
  "status": {},
  "route": [],
  "trajectory": [],
  "objects": []
}
```

All fields except `type` are optional. The frontend consumes `pose`, `status`, `route`, `trajectory`, and `objects` when present.

### `vehicle_pose`

Vehicle localization in the map frame.

```json
{
  "type": "vehicle_pose",
  "timestamp": 1710000000000,
  "frame_id": "map",
  "x": 23.5,
  "y": 14.9,
  "z": 0.0,
  "roll": 0.0,
  "pitch": 0.0,
  "yaw": 1.57,
  "speed": 1.2,
  "child_frame_id": "base_link",
  "tf_delay_ms": 36,
  "pose_age_ms": 80,
  "map_alignment": "已校准",
  "yaw_source": "localization"
}
```

Required fields:

- `x`
- `y`

Recommended fields:

- `timestamp`
- `frame_id`
- `z`
- `yaw`
- `speed`
- `child_frame_id`
- `tf_delay_ms`
- `pose_age_ms`
- `map_alignment`
- `yaw_source`

Frontend aliases:

- `frame_id`, `frameId`, `header.frame_id`
- `child_frame_id`, `childFrameId`, `childFrame`
- `x`, `position.x`, `pose.position.x`
- `y`, `position.y`, `pose.position.y`
- `z`, `position.z`, `pose.position.z`
- `yaw`, `heading`, `theta`
- `speed`, `velocity`, `linearVelocity`
- `tf_delay_ms`, `tfDelayMs`, `transform_delay_ms`
- `pose_age_ms`, `poseAgeMs`
- `map_alignment`, `mapAlignment`, `pcd_osm_alignment`, `pcdOsmAlignment`
- `yaw_source`, `yawSource`, `headingSource`

The frontend does not accept or convert quaternions. The Gateway must publish `yaw`.

Recommended Gateway yaw conversion:

```text
yaw = atan2(
  2 * (w * z + x * y),
  1 - 2 * (y * y + z * z)
)
```

### `vehicle_status`

Vehicle state shown in the status bar.

```json
{
  "type": "vehicle_status",
  "timestamp": 1710000000000,
  "mode": "auto",
  "battery": 54.4,
  "localizationStatus": "normal",
  "gear": "auto"
}
```

Frontend aliases:

- `mode`, `drivingMode`
- `battery`, `batteryPercent`, `soc`
- `localizationStatus`, `localization`
- `gear`, `shift`, `driveGear`

Recommended enum values:

- `mode`: `auto`, `manual`
- `localizationStatus`: `normal`, `stale`, `timeout`, `degraded`, `error`

### `route`

Coarse route result from Autoware / Gateway.

```json
{
  "type": "route",
  "timestamp": 1710000000000,
  "frame_id": "map",
  "points": [
    { "x": 23.5, "y": 14.9 },
    { "x": 25.0, "y": 16.2 }
  ]
}
```

The frontend renders `route` as the coarse route layer. At least two valid points are required.

Accepted type aliases:

- `route`
- `route_points`

### `trajectory`

Drivable trajectory generated by Autoware Planning.

```json
{
  "type": "trajectory",
  "timestamp": 1710000000000,
  "frame_id": "map",
  "points": [
    { "x": 23.5, "y": 14.9, "yaw": 0.2, "velocity": 1.2 },
    { "x": 24.0, "y": 15.3, "yaw": 0.4, "velocity": 1.2 }
  ]
}
```

The frontend applies `trajectory` only when `planningMode` is `autoware`. At least two valid points are required.

Point aliases:

- `x`, `position.x`, `pose.position.x`
- `y`, `position.y`, `pose.position.y`
- `yaw`, `heading`, `theta`
- `velocity`, `speed`, `longitudinal_velocity_mps`

### `perception_objects`

Detected or predicted objects in map coordinates.

```json
{
  "type": "perception_objects",
  "timestamp": 1710000000000,
  "frame_id": "map",
  "objects": [
    {
      "id": "object-1",
      "label": "vehicle",
      "x": 25.0,
      "y": 17.0,
      "yaw": 0.3,
      "length": 1.4,
      "width": 0.8,
      "speed": 0.7,
      "vx": 0.67,
      "vy": 0.21,
      "predictedPath": [
        { "x": 25.0, "y": 17.0 },
        { "x": 25.8, "y": 17.3 }
      ]
    }
  ]
}
```

Accepted type aliases:

- `perception_objects`
- `detected_objects`
- `objects`

Recommended object categories:

- `vehicle`
- `pedestrian`
- `bicycle`
- `unknown`

Object aliases:

- `id`, `uuid`, `object_id`
- `label`, `type`, `classification`, `semantic.type`
- `position`, `pose.position`, `kinematics.pose_with_covariance.pose.position`
- `dimensions`, `shape.dimensions`
- `velocity`, `twist`, `kinematics.twist_with_covariance.twist.linear`
- `predictedPath`, `predicted_path`, `predicted_paths[0].path`

The frontend can filter rendered objects by category and estimates these debug-only safety values:

- nearest obstacle distance
- whether any visible object entered the frontend safety zone
- whether any visible object is near the forward trajectory preview
- rough TTC estimate

These frontend values are for visualization and test triage only. Authoritative safety decisions must come from Autoware / Gateway / vehicle control systems.

## Goal Submission

In `autoware` planning mode, the frontend submits a goal to `planningEndpoint` first, and falls back to `routeEndpoint` when no planning endpoint is configured.

HTTP method: `POST`

```json
{
  "type": "set_goal",
  "protocol": "ros2_gateway.v1",
  "source": "car_ui",
  "frame_id": "map",
  "start": {
    "x": 20.0,
    "y": 13.5,
    "z": 0,
    "yaw": 0,
    "frame_id": "map"
  },
  "goal": {
    "x": 23.5,
    "y": 14.9,
    "z": 0,
    "yaw": 0,
    "frame_id": "map"
  },
  "timestamp": 1710000000000
}
```

The Gateway should validate that `start.frame_id`, `goal.frame_id`, and top-level `frame_id` are compatible with the Autoware map frame. It should then convert this request to the corresponding Autoware goal / route planning input and publish `route` and `trajectory` messages back through the WebSocket.

## Frontend Consumption Rules

- `vehicle_pose` updates car position, yaw, speed, frame display, and localization status.
- `vehicle_status` updates driving mode, battery, localization status, and gear.
- `route` updates the coarse route layer.
- `trajectory` updates the drivable path only in `autoware` mode.
- `perception_objects` updates object boxes, velocity arrows, and predicted paths.
- Messages with unknown `type` are ignored.
- Invalid point arrays with fewer than two usable points are ignored.

## ROS2 Gateway Mapping

Recommended Autoware topic mapping:

- `/localization/kinematic_state` -> `vehicle_pose`
- `/tf` and `/tf_static` -> pose frame checks and TF delay fields
- vehicle state / diagnostics topics -> `vehicle_status`
- route output -> `route`
- planning trajectory output -> `trajectory`
- `/perception/object_recognition/objects` -> `perception_objects`

The Gateway owns all ROS2-specific conversion, including QoS handling, message timestamp conversion, quaternion-to-yaw conversion, frame transform checks, and map-frame normalization.

The exact type of `/localization/kinematic_state` can vary across Autoware deployments. Confirm it on the target vehicle with:

```bash
ros2 topic info -v /localization/kinematic_state
```

The first localization integration should subscribe to:

- `/localization/kinematic_state`
- `/tf`
- `/tf_static`

The frontend coordinate check panel expects:

- `pose.frame_id`: usually `map`
- `child_frame_id`: usually `base_link`
- `tf_delay_ms`: delay for the `map -> base_link` transform
- `pose_age_ms`: age of the localization sample
- `map_alignment`: `已校准` or `未校准`
- `yaw_source`: `localization`, `tf`, or `fallback`
